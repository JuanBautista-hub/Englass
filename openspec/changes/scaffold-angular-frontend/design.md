## Context

The recent `improve-engclass-system-prompt` change rewrote `front-prompt.md` into a normative, comprehensive spec for an Angular 17+ frontend module (a11y, performance, signals, CSRF, envelope errors, autosave with caps, lifecycle). The `scaffold-shared-types-package` change shipped `packages/shared` (`@engclass/shared`) so the app has a single source for `Annotation`, DTOs, and the error envelope. But `apps/` is still empty — there is no runnable app and no visual surface.

This change scaffolds `apps/web` so the prompt becomes executable code. The key constraint is that we want a **visually exercisable UI** even though there is no backend yet. We resolve this by shipping a tiny, opt-in `MockApiService` that returns a bundled 1-page PDF fixture and in-memory submissions, gated behind `environment.useMockApi`. With the mock on, the app boots to a working annotation editor with no other dependencies; with it off, it talks to `/api/v1` via `API_BASE_URL`.

Stakeholders: Engclass maintainer, and any AI/engineer using the prompts.

## Goals / Non-Goals

**Goals:**
- Create a working Angular 17+ workspace at `apps/web` that satisfies every requirement in `openspec/specs/frontend-system-prompt/spec.md` plus the additional constraints listed in `front-prompt.md`.
- Make the app visually runnable today, without a backend, via an opt-in mock layer.
- Strict TS, signals everywhere, a11y-by-construction, performance budgets enforced in code.
- ≥ 70% statement coverage for services and components, lint zero warnings, both gates enforced by CI-quality scripts.

**Non-Goals:**
- Building the backend or wiring it to real auth (separate change).
- Implementing collaborative editing, real-time sync, or grading UI (separate changes).
- SSR / SSG — the editor is heavy-state and per-user; client-only is fine for Fase 1.
- Replacing pdfjs-dist with another engine or adopting `ngx-extended-pdf-viewer` (explicitly forbidden by the prompt).
- i18n catalogs.
- Replacing the Angular CLI's tooling choices (`@angular-devkit/build-angular:application` builder, `jest-preset-angular`).

## Decisions

### 1. Angular CLI workspace generated manually, not via `ng new`
We author `apps/web/{angular.json,tsconfig.*.json,package.json}` by hand rather than running `ng new`, because:
- We want project references to `packages/shared` baked in from day one (the CLI doesn't do this).
- The CLI pulls in a lot of boilerplate (Karma, polyfills, environments by default) that we replace anyway.
- We can pin the Angular minor version exactly (currently 17.3.x, the latest 17 line).

Alternatives considered:
- Run `ng new` then patch → rejected: patching a generated tree is more error-prone than authoring the minimal set of files.
- Nx → rejected: brings a graph/cache layer that we don't need yet.

### 2. ESBuild application builder
Use `@angular-devkit/build-angular:application` (the post-Angular-17 default). It is faster than the old browser builder, supports SSR by default but we keep it off, and plays well with Tailwind via PostCSS.

### 3. Jest via `jest-preset-angular` instead of Karma/Jasmine
The prompt requires Jest. `jest-preset-angular` provides the `jest-preset` transformer and `setup-jest.ts` glue needed to compile Angular templates and `provideRouter` / `provideHttpClient` test wiring. We also add `jest-preset-angular/setup-jest` so `TestBed.initTestEnvironment(...)` is configured once.

Alternatives considered:
- Vitest → rejected: requires more wiring with Angular's AOT pipeline today.
- Karma → rejected: not what the prompt says.

### 4. Tailwind via PostCSS in `angular.json`
No external plugin needed; Angular's application builder already runs PostCSS if a `postcss.config.js` exists. We ship a 1-line config that points to Tailwind.

### 5. PDF fixture shipped inside `apps/web/src/assets/fixtures/demo.pdf`
A minimal 1-page PDF (`A4` size, 595×842 points) generated by `pdf-lib` at build-time via a one-shot `pnpm run fixtures:build` script. This way `apps/web` is fully self-contained and `pnpm start` works offline.

Alternatives considered:
- Hardcode the fixture's binary content in TS → rejected: ugly, no diff-review friendly.
- Fetch from a CDN → rejected: breaks offline / first-paint determinism.

### 6. Mock API is opt-in, environment-gated, behind a thin facade
`MockApiService` implements the same shape as `PdfEditorService` (returns `Observable<...>` of mocked responses) and is bound only when `environment.useMockApi === true`. Production wiring always uses the real `HttpClient`. Both paths go through the same `csrf.interceptor.ts` (the mock honors `X-CSRF-Token` like a real backend would).

Alternatives considered:
- MSW (Mock Service Worker) → rejected: extra build-time layer for Fase 1; we can adopt it later if we add e2e.
- Always-on mock → rejected: violates the prompt's "all calls go to /api/v1" rule when production-bound.

### 7. Signals-first; no NgRx for Fase 1
The prompt's state model (annotations, loading, error, lastSavedAt, activePage, isInputOpen) fits comfortably in plain signals plus a single coordinating service (`PdfEditorService`). Adding NgRx would be premature; we can introduce it later if cross-feature state grows.

Alternatives considered:
- Component Store (`@ngrx/component-store`) → rejected: minimal upside for this scope.
- Plain RxJS `BehaviorSubject` → rejected: the prompt explicitly mandates Signals.

### 8. Coordinate conversion lives in `PdfRendererService`, never in components
`screenToPdfPoint` / `pdfPointToScreen` are pure functions over `(canvas, scale, viewport)`. Putting them in the service (and unit-testing them) is the only way to keep the "persist in user-space" rule auditable. Components receive numbers in user-space and never call `convertToPdfPoint` themselves.

### 9. Keyboard map: declarative `keydown` host listener per component
We attach `(keydown)` listeners in component templates and dispatch to small handler functions. A global `KeyboardService` would be overkill for two components.

### 10. Test environment: `jsdom` for services, real Angular `TestBed` for components
`jest-preset-angular` already brings jsdom. We use `TestBed.configureTestingModule({ providers: [provideHttpClient(), provideHttpClientTesting(), provideRouter([])] })` for component tests; pure services run with plain Jest.

### 11. Lint: zero warnings is enforced by CI-style scripts
`pnpm lint` runs `eslint --max-warnings=0`. `pnpm test` runs `jest --coverage` and `coverageThreshold` blocks below 70%.

### 12. Lazy-loading via `loadChildren` for the feature module
`app.routes.ts` uses `loadChildren: () => import('./features/pdf-editor/pdf-editor.routes').then(m => m.routes)`. The auth guard lives in the lazy-loaded route so it's also code-split.

## Risks / Trade-offs

- **Risk**: pdfjs-dist ESM-only migration — the latest pdfjs-dist version requires a specific `workerSrc` setup. → **Mitigation**: pin pdfjs-dist to a version that still ships a UMD-style worker URL (`pdfjs-dist@4.x`), import it as a side-effect, set `GlobalWorkerOptions.workerSrc` to the bundled `pdf.worker.min.mjs` from `node_modules/pdfjs-dist/build/`.
- **Risk**: hand-authored `angular.json` is brittle against Angular CLI upgrades. → **Mitigation**: pin Angular major version; document the upgrade path in `apps/web/README.md`.
- **Risk**: the mock API could leak into production if `environment.useMockApi` is mis-shipped. → **Mitigation**: add a runtime assertion at bootstrap that logs a console.warn when the mock is active; production builds assert `environment.useMockApi === false` via an `ng build` step's `fileReplacements`.
- **Risk**: 500-annotation / 256 KB cap is enforced client-side but a backend change can reject a payload that passes locally. → **Mitigation**: the error envelope handler treats 4xx with `code: 'VALIDATION'` or `'INVALID_FILE'` as terminal UI errors; user copies the `requestId` and retries.
- **Risk**: progressive mount policy can desync from `activePage` if scroll is very fast. → **Mitigation**: debounce the scroll handler with `requestAnimationFrame`; `IntersectionObserver` is used to track which pages are in view, `requestIdleCallback` schedules off-viewport renders.
- **Risk**: pdfjs-dist coordinate rounding drift across versions. → **Mitigation**: round to 2 decimals on write (per the prompt) and round-trip in unit tests.

## Migration Plan

This change does not deploy runtime code to production. Migration is purely additive:
1. Apply all files in `apps/web/`.
2. Run `pnpm install` at the root (adds `@engclass/shared`, `@angular/*`, `pdfjs-dist`, etc.).
3. `pnpm --filter @engclass/web start` (or `pnpm --filter @engclass/web build` for prod bundle) works.
4. Default route `/editor/demo` opens the mock-fixture editor; toggle `environment.useMockApi` to point at the real backend once it lands.
5. Follow-up changes (`add-real-auth`, `wire-grading-ui`) will edit specific services/components without touching the workspace skeleton.

Rollback: delete `apps/web/` and revert the root `pnpm install` lockfile change. Single git revert covers it.
